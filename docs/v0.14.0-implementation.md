# 0.14.0 实现记录：资源导入导出与文件浏览

> 本文件记录**实现过程中确认下来的事实**与**取舍的理由**，供后续迭代（尤其 `1.0.0`
> 的收口）直接引用。设计目标与验收见 [roadmap.md](./roadmap.md) 的 0.14.0 段，
> 接口约定见 [api-spec.md](./api-spec.md)。

## 一、先确认再动手：实测得到的 Docker 行为

这些结论都是在本机守护进程上跑出来的，**不要凭印象重新推导**；有几条与社区常见说法相反。

| 行为 | 实测结论 | 影响 |
|------|----------|------|
| `Images.LoadImageAsync` 是否要求可 seek 的流 | **不要求** | 20 GB 上传可以边收边喂，不必先落盘 |
| `SaveImagesAsync(string[])` 是否保留全部标签 | **保留** | 按**镜像引用**导出即可，不必自己拼标签 |
| 未启动（`created`）容器的 `/archive` | **读写都可用** | 卷浏览的辅助容器**不需要跑起来** |
| `statOnly` 能否列目录 | **不能**（只回单个 stat） | 列目录只能读 tar 条目头 |
| archive 的 tar 条目名是否带前导 `/` | **Docker 29.x 不带** | 比较路径必须两侧都规范化 |
| `docker export` 是否含卷内容 | **不含** | 界面必须写明「这不是备份」 |
| 暂停容器的 export / archive | **可用** | 不必强制用户先恢复容器 |
| 卷的 `force` 删除能否删掉被引用的卷 | **不能** | `force` 只让「卷不存在」变成成功 |

## 二、几个关键取舍

### 1. 导出为什么是「后台任务 + 票据下载」

`docker save` 一个几 GB 的镜像要几分钟。同步 HTTP 响应会被反代先掐断（nginx 默认
`proxy_read_timeout 60s`），用户拿到的却是「504 网关超时」而不是「导出失败」——
这两件事的处置方式完全不同。

因此：`POST export` 只登记任务并返回 `jobId`，**权威状态在 `export/status`**
（SignalR 只是提示，断线重连后仍要靠轮询收敛），产物通过**一次性票据**下载。

票据而不是 access token 的原因：`<a href>` 与浏览器原生下载都带不了
`Authorization` 头，把 access token 拼进 URL 会写进访问日志与浏览器历史。票据只能
换一个文件、且很快过期，泄露代价有界。

### 2. 导出产物为什么按 `<32位十六进制>.tar` 命名

清理服务会删除临时目录里的过期产物。若产物名由**调用方**决定（比如直接用容器名），
一次误配就可能让清理逻辑删到别的文件（实测踩过：早期版本直接清空整个目录，跨测试
宿主时会互删）。

现在只有「32 位小写十六进制 + `.tar`」这种形态会被当作产物删除，别的文件一律不碰。

### 3. 卷文件浏览为什么用一次性辅助容器

Docker 只给**容器**提供文件接口（`/containers/{id}/archive`），卷没有。只能把卷挂进
一个容器再读。

辅助镜像 `whalefleet/volfs-helper` 的做法：

- `scratch` 打底，约 **10 kB**，只放一个占位文件；
- 容器的 `Cmd` 是 `["/whalefleet-file-browser"]`，**永远不启动**（`archive` 对
  `created` 容器可用）；
- 用完在 `finally` 里 `Force` 删除——失败路径也要删，否则每失败一次留一个垃圾容器。

⚠️ **不要给它加功能**（比如塞个 tar 进去"顺便解包"）：一旦它需要执行，就得有 libc
与 shell，体积、GPLv2 许可与攻击面三条优势同时消失。

镜像分发：0.x 期间**不发布**，`make volfs-helper` 本机构建一次；缺失时后端按需
`pull` 一次，拉不到才报错并给出构建命令。`1.0.0` 起改由发布流水线推 GHCR。

### 4. 反向生成：一个读原文，一个重建

两条路看起来对称，实际语义完全不同：

| 对象 | 数据来源 | 为什么 |
|------|----------|--------|
| Compose 项目 | **库里存的 YAML 原文** | 原文就存在（部署时写入）。重新生成会丢注释、锚点与键序，而用户要的是「原本部署的那份文件」。未受管的项目**没有**原文，报 `1903` 而不是给一份猜出来的定义 |
| 容器 | **原始 inspect，现场重建** | 从来没有「容器的原文」这回事。⚠️ 必须读**原始 inspect**：现有 `ContainerDetail` 是为展示服务的投影，刻意不含 `capAdd` / `sysctls` / `devices` / `ulimits` / `logConfig` / `healthcheck` / 端口绑定的宿主 IP，用它生成会**静默丢配置** |

生成侧的两个易错点：

- **`docker run` 的参数必须 shell 转义**。一个含空格的 env 值不转义会被 shell 拆成
  两个参数——命令看起来对，跑起来参数错位。统一用 POSIX 单引号（规则只有一条：
  值里的 `'` 写成 `'\''`）。
- **健康检查的时长必须带单位**。`TimeSpan.ToString()` 给的是 `00:00:30`，Docker
  对它**不报错地当成 0**（于是健康检查每毫秒跑一次）。统一格式化成 `30s` / `1m30s`。

### 5. 授权放在请求期，不放在后台线程

容器的导出、提交、文件写入都在**请求期**做完 `container.write` 判定并把规范化后的
容器 ID 入队。原因：后台工作线程没有 `ICurrentUser`，在那里判权限要么直接失败
（用户的合法操作被拒），要么退化成「信任入队时给的 ID」（越权）。

同理，`containers/run-command` 只要求 `container.read`：生成结果里没有任何详情的
**新**信息——能打开详情页的人本来就看得到这些参数。

## 三、配置项

| 键 | 默认 | 说明 |
|----|------|------|
| `Files:AllowWrite` | `true` | 关闭后所有文件写入回 `1409`。默认开启的理由：浏览的主要用途是「拷出来改完放回去」，默认关掉功能形同虚设；写入本身另有 `container.write` / `volume.write` 权限门 |
| `Files:MaxUploadBytes` | 20 GB | 导入与文件写入的上限。**必须 ≤ 反代的上限**，否则请求在反代就被拒，应用日志里什么都没有 |
| `Files:TempDirectory` | 空（→ `data/exports`） | 导出产物目录。集成测试必须显式指定到临时目录，否则会写进仓库 |
| `Files:TicketTtl` | 10 分钟 | 下载票据有效期 |
| `Files:ExportTtl` | 1 小时 | 产物保留期，超时由清理服务删除 |
| `Files:MaxConcurrentExports` | 2 | 同时执行的导出任务数 |
| `Files:HelperImage` | `whalefleet/volfs-helper:0.14.0` | 卷浏览的辅助镜像 |
| `Files:SweepInterval` | 1 分钟 | 过期清理的扫描周期 |
| `Files:MaxListEntries` | 5000 | 单次目录列举的条目上限，超出回 `truncated` |

## 四、部署与反代

- **socket-proxy 模式**需要放行 `IMAGES=1` / `CONTAINERS=1` / `POST=1`：卷浏览要
  创建与删除辅助容器，导出要读镜像。
- **nginx**：`client_max_body_size` 要 ≥ `Files:MaxUploadBytes`；下载路径
  （`/api/v1/hosts/{hostId}/{images,containers}/download`）要 `proxy_buffering off`，
  否则几 GB 的响应会先被攒进内存 / 临时盘。默认 `proxy_read_timeout 60s` 对导出轮询
  够用（纯 JSON），但下载大文件同样需要放宽。
- **Traefik**：默认不缓冲响应，与 nginx 相反；`maxRequestBodyBytes` 同样要抬到上限
  之上。

## 五、测试口径

- 集成测试**必须**自建几 KB 的探针镜像（`docker import` 一个空 tar），不要用宿主机上
  已有的镜像——它们可能几个 GB，还会在别人的镜像库里留垃圾。
- 卷浏览的集成测试跑完要断言**没有残留辅助容器**（标签 `whalefleet.role=file-browser`）。
- 「同一镜像的重复导出复用同一任务」这条用例**不能硬断言 `reused=true`**：探针镜像
  几 KB，机器空闲时第一次导出可能已经跑完，此时第二次启动新任务是正确行为。
  实测全量跑时偶发失败，现已改为「复用时必须是同一个 `jobId`；未复用时必须是不同的
  `jobId`」。
