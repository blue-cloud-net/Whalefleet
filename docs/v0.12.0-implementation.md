# 0.12.0 容器粒度 RBAC 实施记录

## 授权语义

主机有效权限保持既有全局与主机角色的并集规则；容器分配不参与主机权限和主机可见性计算。
对目标容器存在分配时，先合并该容器各角色，再与主机权限取交集，只保留 `container.read/write`。
两项权限独立，不隐式互相包含。不同主机上的同 ID 互不影响。

- `inheritHost`（默认）：目标容器没有分配时继承主机权限。给 A 分配 viewer 不影响 B。
- `requireAssignment`：目标容器没有分配时拒绝访问。
- 只有内置 admin 的**全局分配**可短路；主机 admin 和容器 admin 均不能扩大作用域。
- 默认模式撤销最后一条容器分配会**恢复主机权限**，不是撤销全部访问。管理界面按查询时策略分别提示。

例如主机有 read/write、A 为 viewer：A 只读，B 默认继承 read/write；切严格模式后 B 不可访问。
主机只有 read 时，即使 A 为 operator 也不能写。

## 数据与接口

迁移 `0012_container_rbac.sql` 保留既有授权，增加 nullable `container_id`、主机配对约束与覆盖 NULL 的有效分配唯一索引。
新增 `authorization_settings` 单行持久化实例策略。

用户及主机视角的角色分配请求增加可选 `containerId`。用户视角仍用 `host`（主机名）；主机视角由路径确定主机。
授予时将名称、短 ID 解析为完整 ID，重复授予返回原分配；撤销使用保存的完整 ID，不要求 Docker 对象仍存在。
分配响应增加 `containerId` 与 `containerPermissionMode`，后者用于说明撤销后果。

容器列表与详情返回 `effectivePermissions`，供按钮显隐使用；服务端始终独立鉴权。
设置端点为 `POST /api/v1/admin/settings/authorization/get` 与 `update`，仅内置全局管理员可访问。
更新请求为 `{ "containerPermissionMode": "inheritHost" }` 或 `requireAssignment`，未知值返回 `1000`，权限不足返回 `1502`。
设置写入活动审计，下一请求读取新值。

`IPermissionChecker` 继续负责主机上限，新增 `IContainerPermissionChecker` 负责容器交集与批量读取复用；
应用用例通过 `ContainerAuthorizationService` 统一解析目标与检查权限。请求内缓存分配、角色及容器判定，长连接复核使用新作用域。

## 覆盖与生命周期

- 列表先授权过滤再排序、分页和统计 total；健康批量查询沿用并发 8 的 inspect，返回前按完整 ID 过滤。
- 详情、生命周期写操作、日志读取与下载、终端令牌和 WebSocket 建立均校验容器权限。
- SignalR 日志、指标及终端每 5 秒复核，权限丢失后取消订阅或断开会话。
- 网络详情、Compose 关联容器、主机容器计数和容器通知按 read 过滤；通知列表、未读计数及已读操作共用过滤条件。
- 网络接入/断开及关联镜像、卷删除检查受影响容器。容器能力收窄时禁止创建、复制、资源 prune 与 Compose 整项目写入。
- 平台重建和追加挂卷在成功后事务迁移有效授权。主机级互斥协调重建、授予和撤销，防止旧 ID 的并发授权遗漏。
- 创建、启动或授权迁移失败时恢复旧容器与原分配；外部删除重建及 duplicate 不继承授权。

前端用户授权对话框及容器详情提供容器分配入口，展示主机权限上限与当前交集；全局设置提供策略卡片。
Mock 授予复用容器会话数据，将名称和短 ID 规范为完整 ID，并支持删除后撤销。
